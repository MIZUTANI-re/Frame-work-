# タスク票 M1：土台（ログイン・授業・招待コード・班分け・Teams 風の枠）

> 状態: 未着手（本人の確認待ち）　設計: Opus　実装: Sonnet　レビュー: Opus
> 前提の設計: [概要設計](../design/01_overview.md) §3・§4・§6・§7・§8、決定 D-001〜D-011

## 目的
付箋ボード（M2）を載せる前の土台を作る。教員が授業を作り、学生が招待コードで入り、教員が班に分け、学生は自分の班だけが見える。ここで「一方通行の権限」をサーバー側で確かめる仕組みを固める。

## 作るもの
1. **教員アカウントの作成コマンド**: `python -m app.cli create-teacher --name <名前>`（パスワードは対話入力）
2. **ログイン / ログアウト**: 名前 + パスワード。教員・学生とも同じ画面
3. **授業の作成（教員）**: 授業名を入れると招待コードが自動で付く。コードは 6 文字、紛らわしい文字（0 O 1 I L）を使わない。再発行できる
4. **授業への参加（学生）**: `/join` で「招待コード + 名前 + パスワード」
   - 名前が未使用 → 学生として登録して参加
   - 名前が使用済みでパスワードが合う学生 → その人として参加を追加
   - それ以外 → エラー（「その名前は使われています」）
5. **班分け（教員）**: 班の作成・名前変更・削除。学生を班に入れる（手動）。班の数を指定してランダムに振り分ける
6. **Teams 風の枠**: 左端に授業一覧、2 列目に班一覧、メインに班のページ（M2 でボードのタブが入る場所。今は「ボードは M2 で追加」と表示）
   - 学生: 2 列目には自分の班だけ。教員の項目は出さない
   - 教員: 全班と「メンバー管理」「招待コード」を出す

## 権限（必ずサーバー側で確かめる）
| アクセス | 教員（担当） | 教員（担当外） | 学生（その班） | 学生（他の班・未参加） |
|---|---|---|---|---|
| 授業ページ | ○ | 404 | ○（自分の班だけ見える） | 404 |
| 班ページ | ○ | 404 | ○ | 404 |
| 班分け・コード再発行 | ○ | 404 | 403 | 404 |

- 存在を知られたくない所は 404 を返す（403 だと「ある」ことが分かる）
- 権限チェックは 1 か所の関数（例 `require_course_teacher` / `require_team_member`）にまとめ、各ルートで使う

## 技術の指定
- Python 3.12 以上 / FastAPI / Uvicorn / SQLAlchemy 2.0（`Mapped` 型の書き方）/ SQLite（`data/app.db`）/ Jinja2 / 素の JS（ES Modules）/ CSS
- パスワード: `pwdlib[argon2]` でハッシュ化。平文は保存もログ出力もしない
- セッション: Starlette の `SessionMiddleware`（`SECRET_KEY` は環境変数か `.env`。無ければ起動時に警告して開発用の値）
- テーブルは起動時に `create_all`（Alembic はまだ使わない）
- 依存は `requirements.txt` に固定版で書く
- M2 以降で使う Board・Note・Cluster・Vote・Event テーブルは **まだ作らない**。Event だけは「参加した」「班に入った」を記録するために M1 で作る


## 完了の条件（テストで確かめる）
- [ ] 教員がログインして授業を作ると、6 文字の招待コードが付く
- [ ] 学生が正しいコードで参加でき、間違ったコードでは参加できない
- [ ] 同じ名前で別のパスワードを入れると参加できない
- [ ] 教員がランダム振り分けをすると、全学生がどれか 1 つの班に入り、班の人数の差が 1 以下
- [ ] 学生 A は自分の班のページを開けるが、他の班・担当外の授業は 404
- [ ] 学生は班分け・コード再発行の操作ができない
- [ ] 担当外の教員は他の教員の授業を開けない
- [ ] パスワードが DB に平文で入っていない
- [ ] 参加・班への追加が Event に記録される
- [ ] `pytest` が全部通る。README の手順で起動できる
