## 目的
付箋ボード（ステップ 2）を載せる前の土台を作る。教員が授業を作り、学生が招待コードで入り、教員が班に分け、学生は自分の班だけが見える。ここで「一方通行の権限」をサーバー側で確かめる仕組みを固める。

## 作るもの
1. **教員アカウントの作成コマンド**（F-01）：`python -m app.cli create-teacher --name <名前>`。パスワードは対話で入力
2. **ログイン / ログアウト**（F-02・S-01）：名前 + パスワード。教員・学生とも同じ画面
3. **授業の作成と招待コード**（F-03・S-04・S-05）：決まりは機能設計書 §5「F-03」
4. **授業への参加**（F-04・S-02）：決まりは機能設計書 §5「F-04」の表
5. **班分け**（F-05・S-05）：班の作成・名前変更、学生を班に入れる（手動）、班の数を指定してランダムに振り分ける（班は消さない。D-030）
6. **Teams 風の枠**（S-03・S-06）：画面設計書 §2 の配置。班のページのメインには「ボードはステップ 2 で追加」と出す
7. **記録**（F-16）：`course.joined`・`team.member_added`・`team.member_removed` を Event に残す

## 権限（必ずサーバー側で確かめる）
| アクセス | 教員（担当） | 教員（担当外） | 学生（その班） | 学生（他の班・未参加） |
|---|---|---|---|---|
| 授業のホーム | ○ | 404 | ○（自分の班だけ見える） | 404 |
| 班のページ | ○ | 404 | ○ | 404 |
| メンバー管理・コード再発行 | ○ | 404 | 403 | 404 |

権限チェックは `app/security.py` の関数（例 `require_course_teacher`・`require_team_member`）にまとめ、各ルートで使う。

## 作らないもの
- Board・Note・Cluster・Vote のテーブル（ステップ 2 以降）
- WebSocket・フレームワークの定義（ステップ 2）

## 技術の指定
- Python 3.12 以上 / FastAPI / Uvicorn / SQLAlchemy 2.0（`Mapped` 型の書き方）/ SQLite（`data/app.db`）/ Jinja2 / 素の JS（ES Modules）/ CSS
- パスワード：`pwdlib[argon2]`
- セッション：Starlette の `SessionMiddleware`。`SECRET_KEY` は環境変数か `.env`。無ければ起動時に警告し、開発用の値を使う
- テーブルは起動時に `create_all`
- 依存は `requirements.txt` にバージョンを固定して書く
- フォルダは技術設計書 §2 のとおり（`realtime/`・`frameworks/`・`llm/` はまだ作らない）
