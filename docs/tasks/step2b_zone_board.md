## 目的
班のみんなが、ブレストと SWOT のボードに同時に付箋を書けるようにする。書いた付箋は、班の全員の画面にすぐ出る。付箋には作成者が残る。

## 範囲：見た目と最低限の中身（D-046）
- 見た目は見本 v2 のボードに合わせる。
- 付箋は「足す・動かす・消す」と作成者の表示ができればよい。本文を直すのは今は作らない（消して書き直す）。
- 迷ったら止まらず、仮の決定かいちばん単純な形で作り、報告に書く（D-044）。

## 作るもの
1. **ゾーン型の盤面**：定義ファイルの `layout` と `zones` のとおりに区画を並べる（ブレストは 1 マス、SWOT は 2 × 2）。区画の名前とヒントを出す。
2. **付箋**
   - 足す・区画の中や区画の間で動かす・消す（本文を直すのは今は作らない。D-046）。
   - 動かせる・消せるのは、今は書いた本人だけ（他の人の付箋を動かすかは「まとめて聞くこと」B-2 の③）。
   - 消すときは行を残し、`deleted_at` を入れる（D-031）。
   - 作成者の名前を出す。色は作成者ごとに決まった色にする。
3. **リアルタイム同期**（技術設計書 §3）
   - `app/realtime/` に「配信係」を 1 つだけ作る。部屋 = ボード 1 つ。
   - 配信係は「誰に送るか」を人ごとに選べる形にしておく（ステップ 3 の個人ワークで使う）。今はメモリの中の部屋でよいが、差し替えはここだけで済むようにする（M-7）。
   - 画面は `/ws/boards/{id}` につなぐ。http なら ws、https なら wss に自動で切り替える。
   - つなぐときに、セッション Cookie で「誰か」を確かめ、そのボードを見てよい人だけ入れる（担当の先生・その班の学生）。それ以外は理由のコードをつけて切る。
   - 学生がつなげる・書けるのは「いま」のボードだけ。「終わり」のボードは見るだけ、「まだ」のボードは開けない（B-7 の仮の決定）。先生は全部見られる（書かない）。
   - ボードの画面の URL は画面設計書の S-10 `/teams/{id}/boards/{board_id}` に合わせる（今の `?board=` から移す）。
   - 付箋の操作は、サーバーが DB に保存して記録（Event）を残してから、部屋の人に配る。
   - 画面は 30 秒ごとに合図（ping）を送る。切れたら自動でつなぎ直し、ボードの全部を取り直す。
4. **先生は見るだけ**（D-011）：先生には書き込みの部品を出さない。先生から書き込みの送信が来ても、サーバーで断る。
5. **記録**：`note.created`・`note.moved`・`note.deleted`。
6. **テーブル**：`Note` を Alembic の版 0003 で足す（データ設計書のとおり。持ち込みの列 `source_note_id`・`source_cluster_id` も今のうちに入れておく）。

## 作らないもの
- 個人ワークで他の人の付箋を隠す・タイマー・まとめる・投票・結論（ステップ 3）
- 2 軸型（ペイオフ）の盤面（ステップ 4）
- 材料の欄（持ち込み。ステップ 3）

## 完了の条件（テストで確かめる）
- [ ] 同じ班の学生 2 人がつないでいて、1 人が付箋を足すと、もう 1 人に届く（TestClient の WebSocket で確かめる）
- [ ] 他の班の学生・担当外の先生・ログインしていない人は、つなげない
- [ ] 先生はつなげるが、書き込みの送信は断られる
- [ ] 他の人の付箋は、動かせないし消せない
- [ ] 消した付箋は画面から消えるが、DB の行は残る
- [ ] 付箋の操作がすべて Event に記録される
- [ ] つなぎ直したとき、ボードの全部を取り直せる
- [ ] 版 0003 を流した DB とモデルが一致する
- [ ] `pytest` が全部通る
