# 公開

設計は [配置・移行設計書](../08_deployment_design.md)。

## Docker
- **一言で**：アプリと、それを動かすのに要るもの一式（Python・ライブラリ）を 1 つの箱に入れる仕組み。どこで開けても同じように動く。
- **言葉**
  - **Dockerfile**：箱の作り方を書いた設計図
  - **イメージ**：設計図から作った完成品。持ち運べる
  - **コンテナ**：イメージを動かしている状態
  - **docker compose**：複数の箱（アプリとトンネル）をまとめて起動・停止する道具
- **たとえ**：引っ越しのコンテナ。中身をまるごと運べば、新しい家（Azure）でもそのまま使える。
- **このアプリのどこ**：ステップ 1.5 で作る `Dockerfile`・`docker-compose.yml`。
- **確かめる問い**
  - 「自分の PC では動くのに、別の PC では動かない」が、Docker だと起きにくいのはなぜ？

## 環境変数
- **一言で**：置き場所ごとに変わる値（DB の場所・鍵など）を、コードの外から渡す仕組み。
- **たとえ**：同じレシピ（コード）でも、台所（PC / Azure）ごとに置いてある調味料の棚（環境変数）が違う。
- **このアプリのどこ**：`app/config.py`。一覧は配置・移行設計書 §5。
- **確かめる問い**
  - `SECRET_KEY` をコードに直接書いて GitHub に上げると、何が起きる？

## Cloudflare Tunnel
- **一言で**：PC の中のアプリに、外から HTTPS で入れる道を作る仕組み。PC の側から Cloudflare へつなぎに行くので、ルーターの設定が要らない。
- **たとえ**：家から外の受付（Cloudflare）に専用の電話線を引き、受付に来たお客さんだけをその線で家に案内してもらう。
- **このアプリのどこ**：ステップ 1.5 の `docker-compose.yml` の `tunnel`。
- **確かめる問い**
  - Quick Tunnel の URL が、起動のたびに変わるのはなぜ困る？　どうすれば固定できる？

## プロキシヘッダー
- **一言で**：入口（Cloudflare）が「お客さんは元々 https で来ました」とアプリに伝える知らせ（`X-Forwarded-Proto` など）。
- **たとえ**：受付が内線で「このお客さんは正面玄関から来ました」と伝える。
- **このアプリのどこ**：ステップ 1.5 の uvicorn の `--proxy-headers`・`--forwarded-allow-ips`。
- **確かめる問い**
  - この知らせを信じないと、Cookie の `Secure` やリンクの URL がどうおかしくなる？
  - 誰の知らせでも信じると、何が危ない？
