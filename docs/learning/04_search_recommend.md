# 探す・おすすめ（LLM なし）

設計は [フレームワーク設計書 §7](../06_framework_design.md)。

## サジェスト
- **一言で**：文字を打つたびに、合う候補を絞り込んで出す仕組み。インクリメンタルサーチとも言う。Google の検索窓や Ctrl+F と同じ考え方。
- **たとえ**：辞書を引くとき、1 文字目でページを開き、2 文字目でさらに絞る。
- **このアプリのどこ**：ステップ 2 の「フレームワークを選ぶ」画面（S-07）。手札が少ないうちは、一覧を全部画面に送り、ブラウザの JavaScript で絞り込む。
- **確かめる問い**
  - 打つたびにサーバーへ聞きに行く方法と、最初に全部送ってブラウザで絞る方法。手札が 20 個のときと 1 万個のときで、どちらが向いている？

## 文字の正規化
- **一言で**：比べる前に、文字の書き方の違いをそろえること。
- **このアプリでそろえるもの**
  - 全角と半角（`ＳＷＯＴ` と `SWOT`）→ Unicode の NFKC 正規化
  - 大文字と小文字（`swot` と `SWOT`）
  - カタカナとひらがな（`ブレスト` と `ぶれすと`）
- **確かめる問い**
  - 「ぶれすと」と打って「ブレインストーミング」が出るには、正規化のほかに何が要る？（ヒント：別名 `aliases`）

## 人気順
- **一言で**：「何回選ばれたか」を数えて、多い順に並べる。いちばん簡単なおすすめ。
- **このアプリのどこ**：ステップ 2。授業でフレームワークを選んだ回数（`CourseFramework` の行の数）を数える。
- **弱点**：最初は全部 0 回で差がつかない（コールドスタート）。そのときはカタログの順に並べる。
- **確かめる問い**
  - 人気順だけにすると、新しく足したフレームワークが選ばれにくくなるのはなぜ？

## あとで使えるもの
今回は選ばなかったが、記録（Event）が貯まれば使える。AI 系は本人が作る（D-016）。

| 方法 | 一言で | 必要なデータ |
|---|---|---|
| 協調フィルタリング | 「これを選んだ人は、これも選んでいる」。Amazon や YouTube のおすすめの考え方 | どの授業でどれとどれが一緒に選ばれたか |
| キーワードの一致（TF-IDF など） | 授業のテーマの言葉と、説明・タグの言葉の重なりで並べる | フレームワークの `meta`（説明・`good_for`・タグ） |
| LLM・埋め込み | 言葉の意味の近さで選ぶ（pgvector はこの「近さ」を探す道具） | 同上 + モデル（本人が決める） |
