# データ

## SQLAlchemy の ORM
- **一言で**：DB のテーブルを Python のクラスとして書き、1 行を 1 つのオブジェクトとして扱う仕組み。SQL を直接書かなくてよい。
- **たとえ**：Excel の表の 1 行を、名前つきの箱（`user.name`・`user.role`）として持ち歩く。
- **このアプリのどこ**：`app/models.py`（`※ 未習` の印がある）。DB への接続は `app/db.py`。
- **確かめる問い**
  - ORM を使うと、SQLite から PostgreSQL に移るのが楽になるのはなぜ？
  - `relationship` は、テーブルのどの列を使ってつながっている？

## argon2 のハッシュ化
- **一言で**：パスワードを「元に戻せない文字列」に変えて保存する方法。ログインのときは、入力を同じように変えて比べる。
- **たとえ**：指紋。指紋から人は作れないが、本人の指なら一致を確かめられる。
- **このアプリのどこ**：`app/security.py` の `hash_password` と `verify_password`（`※ 未習` の印がある）。
- **確かめる問い**
  - DB が盗まれても、パスワードそのものが漏れにくいのはなぜ？
  - 同じパスワードでも、ハッシュの文字列が毎回違うのはなぜ？（ヒント：ソルト）

## Alembic
- **一言で**：テーブルの形を変えた「履歴」を残し、どの DB にも同じ順で変更をかけられる道具。
- **たとえ**：家のリフォームの工事記録。記録どおりにやれば、別の家（Azure の DB）も同じ形にできる。
- **このアプリのどこ**：ステップ 1.5 で入れる（`alembic.ini`・`migrations/`）。
- **確かめる問い**
  - 起動のたびに「テーブルが無ければ作る」（`create_all`）だけだと、列を足したいときに何が困る？
