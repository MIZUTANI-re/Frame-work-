# データ

## SQLAlchemy の ORM
- **一言で**：DB のテーブルを Python のクラスとして書き、1 行を 1 つのオブジェクトとして扱う仕組み。SQL を直接書かなくてよい。
- **たとえ**：Excel の表の 1 行を、名前つきの箱（`user.name`・`user.role`）として持ち歩く。
- **このアプリのどこ**：`app/models.py`（`※ 未習` の印がある）。DB への接続は `app/db.py`。
- **確かめる問い**
  - ORM を使うと、SQLite から PostgreSQL に移るのが楽になるのはなぜ？
  - `relationship` は、テーブルのどの列を使ってつながっている？

## argon2 のハッシュ化
- **一言で**：パスワードを「元に戻せない文字列」に変えて保存する方法。ログインのときは、入力を同じように変えて比べる。
- **たとえ**：指紋。指紋から人は作れないが、本人の指なら一致を確かめられる。
- **このアプリのどこ**：`app/security.py` の `hash_password` と `verify_password`（`※ 未習` の印がある）。
- **確かめる問い**
  - DB が盗まれても、パスワードそのものが漏れにくいのはなぜ？
  - 同じパスワードでも、ハッシュの文字列が毎回違うのはなぜ？（ヒント：ソルト）

## トランザクションと「同時に動くとき」
- **一言で**：トランザクションは「全部やるか、全部やらないか」の一まとまり。途中で失敗したら rollback（巻き戻し）する。
- **このアプリで起きたこと**
  - ボタンを 2 度押しすると、1 人の学生が 2 つの班に入った → DB の「重複不可」で守り、ぶつかったら rollback して「重なりました」と出すようにした（D-026）。
  - まちがったログインを同時に 30 回送ると、回数が 2 しか増えなかった。どれも「読む → 足す → 書く」を同じ古い値でやったため → DB の 1 回の更新（`failed_logins = failed_logins + 1`）で足す。
- **たとえ**：2 人が同時に同じ黒板の数字を読んで、それぞれ 1 を足して書き直すと、2 増えるはずが 1 しか増えない。
- **確かめる問い**
  - プロセスの中のロック（`threading.Lock`）で守る方法が、サーバーを 2 台にすると効かなくなるのはなぜ？

## UTCDateTime（日時をそろえる自作の型）
- **一言で**：DB に日時を入れるとき・出すときに、必ず UTC にそろえる「変換係」。SQLAlchemy の TypeDecorator で作った。
- **なぜ要る**：SQLite はタイムゾーンを持たず、PostgreSQL は持つ。そろえないと、タイマー（終了時刻と今の比べ）が壊れる（D-027）。
- **このアプリのどこ**：`app/db.py` の `UTCDateTime`。
- **確かめる問い**
  - 画面に出すときだけ日本時間に直すのは、なぜ DB に日本時間で入れるより良い？

## Alembic
- **一言で**：テーブルの形を変えた「履歴」を残し、どの DB にも同じ順で変更をかけられる道具。
- **たとえ**：家のリフォームの工事記録。記録どおりにやれば、別の家（Azure の DB）も同じ形にできる。
- **このアプリのどこ**：ステップ 1.5 で入れる（`alembic.ini`・`migrations/`）。
- **確かめる問い**
  - 起動のたびに「テーブルが無ければ作る」（`create_all`）だけだと、列を足したいときに何が困る？
