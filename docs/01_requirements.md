## 1. 背景
- グループワークでは、先に人の意見を聞くと、考えがそれに引っぱられて固まってしまう。
- コンサルや事業計画で使うフレームワーク（ブレスト・SWOT・As-is/To-be・ガントチャートなど）を、班のみんなで同時に触れる場所が少ない。
- 教員からは、学生がフレームワークの中でどう考えたかが見えない。

## 2. 目的
| # | 目的 |
|---|---|
| G-1 | **考えをまとめる場所をつくる**。招待コードで集まった班が、同じボードに同時に書き込める。付箋には誰が書いたかが残る |
| G-2 | **同調を防ぐ**。最初は他の人の付箋が見えない状態で、各自が書く |
| G-3 | **考え方を可視化する**。学生がフレームワークの中でどう考え・まとめ・選んだかを教員が見る。最初は教員向けの教育支援とする（D-008） |
| G-4 | **人材教育に役立てる**。G-1〜G-3 で、グループワークを「やらせっぱなし」にしない |

## 3. 最終ゴール
教員が授業内容を入れると、AI が用意済みのフレームワークの中から 2〜3 個を、使う順番つきで提案する。AI は 0 から作らず、手札から選ぶ。だから、フレームワークを先に揃えることが土台になる。

## 4. 利用者
| 利用者 | 説明 | 主にすること |
|---|---|---|
| 教員 | 授業を持つ人 | 授業を作る・班に分ける・フレームワークを指定する・見守る・可視化を見る |
| 学生 | 授業に参加する人 | 招待コードで参加する・付箋を書く・班でまとめる |

## 5. 範囲
### 最初のバージョン（MVP）でやる
- ログイン・授業・招待コード・班分け
- フレームワーク 3 本：ブレインストーミング・SWOT・ペイオフマトリクス（D-007）
- 個人ワーク（タイマーで自動公開）→ 公開 → まとめる（手動）→ 投票 → 結論
- 教員の全班閲覧とダッシュボード

### 後でやる
- 残りのフレームワーク（As-is/To-be・KPT・ガントチャート・決定マトリクス、話し合い系・技術コンサル系 など）
- 学生がフレームワークを自由に選ぶ形
- LLM による似た意見のまとめ・要約、授業内容からの推薦
- PostgreSQL・pgvector

### 今のところやらない
- 24 時間いつでも使える公開（今は PC を点けている間だけ。D-017）
- 学校の SSO
- ビデオ通話・音声

## 6. 機能要件
| ID | 要件 | ステップ |
|---|---|---|
| FR-01 | 教員はアカウントを持ち、名前とパスワードでログインできる | 1 |
| FR-02 | 教員は授業を作り、招待コードを発行・再発行できる | 1 |
| FR-03 | 学生は初回「招待コード + 名前 + パスワード」で登録・参加し、次から「名前 + パスワード」でログインできる（D-009） | 1 |
| FR-04 | 教員は班を作り、学生を手動またはランダムで班に分けられる | 1 |
| FR-05 | 教員は班にフレームワークを指定してボードを作れる（D-008） | 2 |
| FR-06 | 学生は自分の班のボードに付箋を書け、班の全員の画面にすぐ反映される | 2 |
| FR-07 | 付箋には作成者と時刻が残る（D-006） | 2 |
| FR-08 | 個人ワーク中、学生は他の学生の付箋を見られない（D-006） | 3 |
| FR-09 | 教員が決めた時間が来たら自動で公開になる。教員は早めることもできる（D-010） | 3 |
| FR-10 | 学生は似た付箋をまとめ、見出しをつけられる | 3 |
| FR-11 | 学生は決められた票数で投票できる | 3 |
| FR-12 | 班は結論を書いて残せる | 3 |
| FR-13 | ペイオフマトリクスでは、付箋を 2 つの軸の上に置ける | 4 |
| FR-14 | 教員は全班のボードを見られる。書き込みはしない（D-011） | 5 |
| FR-15 | 教員はダッシュボードで班ごとの様子（誰が何枚・どの区画・どうまとめ・何を選んだか）を見られる | 5 |
| FR-16 | すべての操作が記録として残る | 1〜 |

## 7. 非機能要件
| ID | 要件 | 状態 |
|---|---|---|
| NFR-01 | PC で動く。必要なのは Docker（手元で試すだけなら Python） | D-002・D-017 |
| NFR-02 | 規模の目安：1 授業 40 人・1 班 3〜6 人・同時に動く授業は 1 つ | 案 |
| NFR-03 | 付箋の追加・移動が、班の他の人の画面に 1 秒以内に出る | 案 |
| NFR-04 | パソコンの Chrome・Edge の最新版で動く。スマホでは使わない | D-043 |
| NFR-05 | 権限はサーバーで確かめ、見せてはいけないデータは送らない。パスワードは平文で持たない | D-005 |
| NFR-06 | 操作の記録は消さない | D-006 |
| NFR-07 | DB は接続先を変えるだけで PostgreSQL に移れる | D-002 |
| NFR-08 | 複数人が外から HTTPS で使える（Cloudflare Tunnel 経由） | D-017 |
| NFR-09 | 同じ箱のまま Azure などへ移れる（[配置・移行設計書](08_deployment_design.md) の M-1〜M-11） | D-020 |

## 8. 制約
- 言語は Python。画面は HTML・CSS・JavaScript（D-001）
- DB はローカルで動かす（D-002）
- LLM のモデルは今は決めない（D-003）
