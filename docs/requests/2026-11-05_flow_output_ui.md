## 3. Claude の考え
### 画面の分け方（R-4・R-6）
見本では、フレームワークを選ぶタブを班のページの中に置いていた。そのため、班ごとに選ぶように見えて分かりにくかった。授業の中を、次の 3 つにはっきり分ける。

| 場所 | 中身 | 使う人 |
|---|---|---|
| ⚙ 準備（設定） | 授業の名前・招待コード／メンバーと班／授業の流れ（フレームワークを探して選ぶ → 並べる → 配る） | 先生 |
| ▶ 授業中 | 班のボード。今のフレームワークと、流れのどこにいるか（① ブレスト → ② SWOT → ③ ペイオフ）を上に出す | 先生・学生 |
| 📄 成果 | 班ごとのまとめシート（文章・画像）。先生は全班を並べて見る | 先生・学生（自分の班） |

### 画像の残し方（R-2）
- 画像を作るのは、班が結論を「確定」したときの 1 回だけにする。ずっと作り続けない。
- 画像はブラウザ（学生や先生の PC）で作り、サーバーに送って保存する。サーバーで重い処理をしない。
- 保存は「保存係」（M-9）を通す。今は PC の `data/outputs/`、Azure に移ったら Azure Blob に差し替える。
- 文章のまとめ（データ）が元で、画像はその「写真」。あとで LLM が読むのは文章のほう。

### LLM の枠（R-3）
- まとめシートには「要約」「似た意見のまとめ」「次にやること」の欄を用意し、今は「LLM はまだありません」と出す。
- 枠に入れる元のデータ（付箋・まとまり・票・結論・チャット）は、全部 DB に残っている（D-031）。LLM をつなぐ日に、作り直しは要らない。
- LLM をつなぐのは本人（D-016）。

### ChatGPT でよいか（R-7）
- **始めるのは ChatGPT（OpenAI）でよい**と考える。ただし、アプリから使うには、ChatGPT の月額の契約ではなく、**OpenAI の API**（使った分だけ払う、別の契約）が要る。
- 大事なのは「どの会社にするか」より「**あとで差し替えられる作り**」。`app/llm/` に入口を 1 つだけ作り、どの会社を使うかは環境変数で切り替える（M-2・M-5 と同じ考え方）。そうすれば、ChatGPT から別の LLM へも簡単に移れる。
- Azure に移るなら、Azure の中で OpenAI のモデルを使う道（Azure OpenAI）もあり、移行の方針と合う。
- 気をつけること：学生が書いた内容を外の会社に送ることになる。大学の決まりと、学生への説明（同意）を確かめる。各社の規約で、送ったデータが学習に使われないかも確かめる。
- 決めるのは本人（D-003・D-016）。未決事項 Q19 に置く。
