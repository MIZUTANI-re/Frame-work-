# フレームワーク設計 v0.2（ドラフト）

> 状態: 壁打ち中　最終更新: 2026-11-05

## 1. 考え方：フレームワーク = 盤面の型 × 区画 × 進め方
フレームワークを 1 つずつ別の画面として作ると、増やすたびにプログラムが増える。そこで 3 つの部品に分け、組み合わせで表す。

| 部品 | 中身 | 例 |
|---|---|---|
| 盤面の型（board type） | 付箋をどう置くか。プログラムはこの型の数だけ作る | ゾーン型・2 軸型・表型・ツリー型・タイムライン型 |
| 区画（zones / axes / columns） | その型の中の具体的なマス | SWOT なら S・W・O・T の 4 マス |
| 進め方（phases） | 時間の流れとルール | 個人ワーク → 公開 → まとめる → 投票 → 結論 |

SWOT・As-is/To-be・KPT・3C・PEST・共感マップは、どれも「ゾーン型」の区画違いにすぎない。ゾーン型を 1 つ作れば、あとは定義ファイルを足すだけで増える。

### 盤面の型
| 型 | 説明 | 当てはまるフレームワーク |
|---|---|---|
| ゾーン型 | 決まったマスに付箋を置く | ブレスト（1 マス）、SWOT、As-is/To-be、KPT、3C、PEST、共感マップ、ビジネスモデルキャンバス |
| 2 軸型 | 縦横の軸の上に自由に置く | ペイオフマトリクス（効果 × 実現しやすさ）、緊急度 × 重要度 |
| 表型 | 行 × 列のセルに値を入れる | 決定マトリクス（案 × 評価基準 × 重み） |
| ツリー型 | 親子でつなぐ | ロジックツリー、なぜなぜ分析、マインドマップ |
| タイムライン型 | 時間軸に棒を置く | ガントチャート |

### 進め方（フェーズ）
どの盤面にも重ねられる共通の部品。
1. **個人ワーク（ブラインド）** — 自分の付箋だけ見える。サーバーは他の学生の付箋を送らない（教員には全員分見える。D-011）。教員が決めた時間が来たら自動で公開へ進む（D-010）
2. **公開** — 全員の付箋が作成者名つきで見える
3. **まとめる** — 似た付箋を重ねてまとまりを作り、見出しをつける
4. **投票** — 1 人 N 票で、付箋かまとまりに投票する
5. **結論** — 班の結論を書く（アウトプット）

どのフェーズをどの順で使うかは、フレームワークごとに定義で決める（例：KPT は投票を使わない）。
Think-Pair-Share や 6-3-5 のように「進め方そのもの」がフレームワークのものは、フェーズの並びとして定義する。

## 2. 定義ファイルの例（SWOT）
```json
{
  "key": "swot",
  "name": "SWOT 分析",
  "board_type": "zone",
  "layout": { "columns": 2, "rows": 2 },
  "zones": [
    { "key": "S", "label": "強み Strengths",      "hint": "内部・プラス" },
    { "key": "W", "label": "弱み Weaknesses",     "hint": "内部・マイナス" },
    { "key": "O", "label": "機会 Opportunities",  "hint": "外部・プラス" },
    { "key": "T", "label": "脅威 Threats",        "hint": "外部・マイナス" }
  ],
  "phases": [
    { "key": "individual", "default_minutes": 7 },
    { "key": "reveal" },
    { "key": "cluster" },
    { "key": "vote", "votes_per_person": 3 },
    { "key": "conclusion" }
  ],
  "meta": {
    "purpose": "analyze",
    "thinking": "converge",
    "group_size": [3, 6],
    "minutes": [20, 40],
    "difficulty": 1,
    "good_for": ["自社・自分の現状把握", "戦略を立てる前の整理"],
    "pairs_with": ["brainstorm", "payoff_matrix"],
    "description": "内部の強み・弱みと、外部の機会・脅威を 4 象限で整理する"
  }
}
```

## 3. AI 推薦のための「メタ情報」
最終ゴール（授業内容 → AI が 2〜3 個を選ぶ）のために、各定義に `meta` を持たせる。AI に渡すのは「この一覧」と「授業内容」だけ。AI は一覧にないものを作らず、選ぶだけ。

| 項目 | 意味 |
|---|---|
| purpose | 何のためか：ideate（発想）/ analyze（分析）/ organize（整理）/ decide（決定）/ plan（計画）/ reflect（振り返り） |
| thinking | diverge（発散）/ converge（収束） |
| group_size | 向いている人数 |
| minutes | 目安の時間（分） |
| difficulty | 1〜3 |
| good_for | 向いている授業・テーマの例 |
| pairs_with | 前後に使うと良いフレームワーク（例：ブレスト → 親和図 → ペイオフ） |

`pairs_with` があると、「2〜3 個を、使う順番つきで」提案できる。

## 4. MVP の 3 本（D-007）
発想 → 分析 → 決定 を 1 本ずつ。作る盤面の型はゾーン型と 2 軸型の 2 つだけ。

| | ブレインストーミング | SWOT | ペイオフマトリクス |
|---|---|---|---|
| key | `brainstorm` | `swot` | `payoff_matrix` |
| 盤面の型 | ゾーン（1 マス） | ゾーン（2 × 2） | 2 軸（横: 実現しやすさ / 縦: 効果） |
| 区画 | テーマ 1 つ | S・W・O・T | 4 象限：すぐやる / 計画してやる / 手が空いたら / やらない |
| 進め方 | 個人ワーク → 公開 → まとめる → 投票 → 結論 | 個人ワーク → 公開 → まとめる → 投票 → 結論 | 個人ワーク → 公開 → 投票 → 結論 |
| 付箋の位置 | 区画の中で自由 | 区画の中で自由 | 軸の上の座標（0〜1 の x, y）。象限は座標から決まる |

## 6. 似た意見をまとめる
- **v1（LLM なし）**: 付箋を別の付箋の上にドロップするとまとまりになる。見出しは手で書く。
- **v2（LLM）**: 公開のときに「似ている候補」を提案し、人が承認する。見出し・要約も提案する。モデルは M6 で決める。
- まとまりは v1 から `Cluster` テーブルで持つので、v2 で作り直さない。

## 7. 可視化のために記録すること
すべての操作を `Event` に追記する（消さない）。今は教員向け（D-008）なので「フレームワークの中でどう考えたか」が中心。学生が自由に選ぶ形を足したときのために、選んだ人も最初から記録しておく。

| イベント | 分かること |
|---|---|
| `board.created`（framework_key・chosen_by つき） | どのフレームワークを、誰が、何番目に選んだか |
| `phase.changed` | 各フェーズにかけた時間 |
| `note.created` / `moved` / `edited` | 誰がどれだけ書いたか（発言の偏り）、どの区画が厚いか |
| `cluster.created` | どうまとめたか |
| `vote.cast` | 何が選ばれたか |

教員のダッシュボードは、この記録から作る。
