設計書の中の言葉は、この表の意味で使う。

## アプリの言葉
| 用語 | 意味 |
|---|---|
| 授業（Course） | 教員が作る集まり。Teams の「チーム」に当たる |
| 招待コード | 学生が授業に入るための 6 文字のコード |
| 班（Team） | 授業の中のグループ。Teams の「チャネル」に当たる |
| ボード（Board） | 班がフレームワークを使って書き込む場所。ボード 1 つ = フレームワーク 1 つ |
| 付箋（Note） | ボードに貼る 1 つの意見。作成者と時刻が残る |
| フレームワーク | 「盤面の型 × 区画 × 進め方」の組み合わせを書いた定義。例: SWOT |
| 盤面の型 | 付箋の置き方の種類。ゾーン型・2 軸型・表型・ツリー型・タイムライン型 |
| 区画（ゾーン） | 盤面の中のマス。SWOT なら S・W・O・T の 4 つ |
| 進め方（フェーズ） | ボードの時間の流れ。個人ワーク → 公開 → まとめる → 投票 → 結論 |
| 個人ワーク（ブラインド） | 他の学生の付箋が見えない時間。同調を防ぐため |
| 公開 | 全員の付箋が作成者名つきで見えるようになること |
| まとまり（Cluster） | 似た付箋を重ねたもの。見出しがつく |
| 結論 | 班としてのアウトプット |
| 記録（Event） | 誰が・いつ・何をしたかの履歴。可視化と AI の材料。消さない |
| ダッシュボード | 教員が記録をまとめて見る画面 |

## 公開の言葉
| 用語 | 意味 |
|---|---|
| Docker（箱） | アプリと、動かすのに要るもの一式をまとめて入れる箱。PC でもクラウドでも同じように動く |
| イメージ | 箱の設計図から作った、持ち運べる完成品。これをそのまま Azure などに置く |
| docker compose | 複数の箱（アプリとトンネル）をまとめて起動・停止する道具 |
| 環境変数 | 置き場所ごとに変わる値（DB の場所・鍵など）を、コードの外から渡すしくみ |
| Cloudflare Tunnel | PC の中のアプリに、外から HTTPS で入れる道を作る Cloudflare のしくみ。PC から外へつなぐので、ルーターの設定が要らない |
| Quick Tunnel | アカウントなしで使える仮のトンネル。起動のたびに URL が変わる。試験用 |
| 入口 | 外からの通信を最初に受け取る所。今は Cloudflare、後で Azure |
| M-番号 | 移行を簡単にする決まり（[配置・移行設計書 §4](08_deployment_design.md)） |

## 開発の言葉
| 用語 | 意味 |
|---|---|
| ステップ | 開発の段階。ステップ 1〜7（[開発計画書](07_development_plan.md)）。研究の「M1（修士 1 年）」と紛らわしいので「M1」という書き方はしない |
| MVP | 最初に動かす最小のバージョン |
| タスク票 | 1 つのステップで作るものを書いた指示書。本人の OK が出てから実装エージェントに渡す |
| エージェント | 役割ごとの Claude。設計・実装・レビュー・フレームワーク作成に分ける |
| D-番号 | [決定ログ](decisions.md) の決定事項 |
| Q-番号 | [未決事項](open_questions.md) の問い |
| FR / NFR | 機能要件 / 非機能要件（[要件定義書](01_requirements.md)） |
| F-番号 | 機能（[機能設計書](02_functional_design.md)） |
| S-番号 | 画面（[画面設計書](03_screen_design.md)） |
| 案 | まだ決まっていないもの。決まったら D-番号をつけて「案」を外す |
