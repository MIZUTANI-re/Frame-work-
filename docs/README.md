## 読む順番
1. 初めて読む人：要件定義書 → 機能設計書 → 画面設計書
2. 実装する人：開発計画書 → タスク票 → 技術設計書・データ設計書
3. フレームワークを増やす人：フレームワーク設計書

## 書き方の決まり
- 「案」と書いた所はまだ決まっていない。決まったら決定ログに D-番号で足し、本文の「案」を外して D-番号を書く。
- 文書を直したら、その文書の「版」と「改訂履歴」を更新する。
