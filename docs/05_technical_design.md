## 1. 技術構成
| 層 | 使うもの | 選ぶ理由 | 後で変えるとき |
|---|---|---|---|
| Web サーバー | FastAPI + Uvicorn | Python。WebSocket が標準で使える。API の説明ページ（/docs）が自動で出る | — |
| リアルタイム同期 | WebSocket | 付箋の追加・移動を班全員の画面へすぐ届ける | サーバーを複数台にしたら Redis Pub/Sub |
| DB | SQLite + SQLAlchemy 2.0 | ローカルでファイル 1 つ。インストール不要 | 接続先 URL を変えて PostgreSQL へ。類似検索は pgvector |
| テーブル変更の管理 | 最初は起動時に自動作成。形が固まったら Alembic | 初期は変更が多いので軽くする | — |
| 画面 | Jinja2 テンプレート + 素の JavaScript（ES Modules）+ CSS | ビルド不要で、Python だけで起動できる | 画面が複雑になりすぎたら React など |
| ログイン | セッション Cookie + パスワードのハッシュ化（argon2） | ローカル運用には十分 | 学校の SSO |
| 教員アカウント | コマンドで作る（`python -m app.cli create-teacher`） | 画面から誰でも教員になれる穴を作らない | 管理画面 |
| テスト | pytest + httpx | FastAPI の定番 | — |
| LLM | **未決**（呼び出し口だけ 1 か所に作る） | 本人の指定（D-003） | ステップ 7 で決める |

## 2. フォルダ構成
```
app/
  main.py          入口。ミドルウェアとルーターを登録する
  config.py        設定（DB の URL、SECRET_KEY）
  db.py            DB への接続
  models.py        テーブルの定義
  security.py      パスワード・ログイン中のユーザー・権限チェック
  invite.py        招待コードの生成
  cli.py           create-teacher コマンド
  routers/         URL ごとの処理（auth / courses / teams / boards / ws）
  realtime/        WebSocket の部屋の管理と配信（ステップ 2）
  frameworks/      フレームワークの定義 JSON と読み込み（ステップ 2）
  llm/             LLM の呼び出し口（ステップ 7。今は空）
  templates/       画面の HTML
  static/          CSS・JavaScript
tests/
data/              SQLite のファイル（Git に入れない）
```

## 3. リアルタイム同期の仕組み（ステップ 2・3）
1. ボード 1 つ = 部屋 1 つ。画面を開くと `/ws/boards/{id}` に WebSocket でつなぐ。
2. つなぐときに、サーバーがセッション Cookie で「誰か」を確かめ、そのボードを見てよい人だけ入れる。
3. 学生が付箋を足すと、サーバーが DB に保存し、記録（Event）を残してから、部屋の人に配る。
4. **個人ワーク中は、配る相手を選ぶ**。付箋の作成・変更は「書いた本人」と「教員」にだけ送る。ほかの学生には送らない。
5. 公開になったら、サーバーが全員に「今のボードの全部」を送り直す。
6. 正しい状態はいつもサーバーの DB。画面がつなぎ直したときは、全部を取り直す。

## 4. タイマー（ステップ 3）
- 個人ワークを始めるとき、終了予定時刻を `Board.phase_ends_at` に保存する。
- サーバーの中で 1 秒ごとに「終了予定を過ぎたボード」を探し、公開に切り替えて全員に知らせる。
- サーバーを再起動しても、DB の時刻から続きができる。
- 画面は残り時間を表示するだけ。画面の時計がずれても、切り替えはサーバーが決める。

## 5. 安全
| 項目 | やり方 |
|---|---|
| パスワード | argon2 でハッシュ化して保存。平文は保存もログ出力もしない |
| ログイン状態 | 署名つきのセッション Cookie（`SECRET_KEY` で署名）。`HttpOnly`・`SameSite=Lax` |
| 権限 | チェックは `security.py` の関数にまとめ、すべてのルートと WebSocket で使う |
| 見せない | 権限のないデータは HTML にも JSON にも WebSocket にも入れない |
| 設定 | `SECRET_KEY` は環境変数か `.env`。`.env` と `data/` は Git に入れない |

## 6. LLM の呼び出し口（ステップ 7）
- `app/llm/` に「似た付箋をまとめる」「要約する」「フレームワークを推薦する」の 3 つの入口だけを決めておく。
- モデルと提供元はステップ 7 で決める（D-003）。それまでは中身を作らない。

## 7. PostgreSQL への移り方（後で）
- SQLAlchemy を使うので、接続先の URL を変えるとほぼそのまま動く。
- SQLite だけの書き方（独自の関数など）は使わない。
- 似た付箋を探す機能は、pgvector を入れたときに足す。
